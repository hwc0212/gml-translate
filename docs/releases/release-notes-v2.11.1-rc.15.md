# GML Translate 2.11.1-rc.15 发行说明

## 本版解决什么

本版解决网站改版后旧翻译错误长期占用完成度、错误数量、重试范围和安全熔断的问题。进度和 AI 工作范围改为基于“当前网站仍实际使用的文本”，而不是把数据库中历次版本的全部队列记录永久相加。

以 CNXHE 为例，旧版显示的 70,256 条失败仍会保留供审计，但当前内容清单完成后，其中已经从网站删除或被新文案替换的记录会显示为历史记录，不再降低当前语言进度，也不会进入正常批次或最多 25 条的有限重试。

## 数据安全

- 不清空 Translation Memory。
- 不删除旧 pending/failed 队列和失败详情。
- 不删除人工译文、术语表、排除规则或语言配置。
- 不自动启动 AI，不恢复暂停任务，不自动重试失败。
- 不修改多语言 URL 或数据库结构。

## 新的统计方式

插件先完成当前站点 resource manifest。完成后，每种语言分开显示：当前已翻译、当前待处理、当前失败、尚未入队，以及不再属于当前站点的历史失败。

只有当前内容覆盖率达到 95%，且当前 SEO 标题、SEO 描述等关键文本全部完成时，语言才达到机器就绪。当前内容清单未完成或存在当前页面渲染错误时，公开 readiness 保持关闭，避免用部分扫描结果发布 hreflang 或索引信号。

## 升级后建议

1. 保持现有翻译暂停状态升级插件。
2. 等待当前内容清单完成，确认后台出现“进度和重试只统计当前网站内容”的提示。
3. 查看各语言的当前 pending、failed 和 not queued；stored history 不需要全部重试。
4. 先测试已保存的 AI Provider，再选择一个语言做最多 25 条的小批量重试。
5. 确认前台目标语言页面、canonical、hreflang 与 Sitemap 后，再逐语言恢复正常队列。

“扫描网站内容”用于更新当前内容清单和发现新文本，不会清空翻译库。需要永久删除插件数据时，仍须在 Settings 的 Uninstall Data Retention 中明确选择并输入 `DELETE`，且只在 WordPress 真正删除插件时执行。

## 验证

已在隔离的 WordPress 7.1、MariaDB 10.11 环境中对 GML Translate 运行完整数据库与路由回归，覆盖根目录、子目录、Queue、Crawler、并发锁、失败恢复、缓存、404、resource readiness、1,500 资源失效恢复和卸载数据保留。测试未调用外部 AI 或 HTTP 服务。
